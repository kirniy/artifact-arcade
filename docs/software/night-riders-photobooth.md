# NIGHT RIDERS and Tickets Cloud night selection

The default theme is `night-riders`. Every published/finished SPb VNVNC Tickets Cloud event whose title contains «ВСЕ СВОИ» overrides it from 23:00 on its Moscow event date until 07:00 the following morning. The venue and organiser IDs are pinned to SPb so Moscow events cannot change this machine. Weekdays alone never override the theme. Removed, draft and cancelled events are excluded. After 07:00 the configured default returns.

The in-process manager uses this selection at boot and while idle/menu selection, deferring changes during an active mode, quest or prize drum. Both the menu and idle animation use the same selector. API polling runs on one daemon thread every five minutes (one minute after failure), with a 10-second timeout per route. If the direct API connection fails, it tries the existing VNVNC website gateway on Yandex Cloud; both routes run only in the background through a dedicated opener that ignores the Pi’s AI proxy variables. The AI proxy configuration is preserved. There are no network waits in the UI loop or capture flow. Sanitized event records are written atomically to `.deploy/club-events.json`; the cache survives power loss and remains usable offline. No key is saved in that cache. Upcoming events must have been fetched before an offline night.

Configuration: `ARTIFACT_CLUB_THEME_SCHEDULE=ticketscloud`, `PHOTOBOOTH_DEFAULT_THEME=night-riders`, `PHOTOBOOTH_THEME=night-riders`, `PHOTOBOOTH_MENU_MODES=night-riders`. Provision `ARTIFACT_TICKETSCLOUD_API_KEY` only into the private device `.env`; never commit or print it. The old shell schedule and updater event activation defer to the in-process scheduler. БАННАЯ activation now selects the same event policy with `bannaya` as its default, instead of disabling ВСЕ СВОИ.

Artwork uses the approved `PRINT/NIGHTRIDERS/masters/01-emblem-final-2k.png`, losslessly resized to 2048 pixels, as an identity-pinned winged shield reference. The 120-second `VIDEOS/night-riders/delivery/02-LED-FAN.mp4` is converted from 720×720 MPEG-4 to silent 128×128 H.264 at 24 fps and looped by the existing frame-cached player. Portraits are nocturnal pixel-rendered 3D heavy-metal scenes: every guest wears a black leather motorcycle jacket, with chrome V-twin cruisers, guitars, fire and cobalt lightning in a gritty midnight environment. Guest identity, pose, ethnicity and count remain locked. The digital image stays dark and full-color; only the thermal print path lifts shadows with a monotonic tonal curve at print resolution. This deterministic conversion adds no AI request and preserves the stamped footer. Generation provider/model and capture settings remain the installed ones.

Deployment: first inspect tracked changes, updater, fresh idle, camera and printer; create a runtime checkpoint and private `.env` backup. Merge/cherry-pick only this release, provision the credential privately, then run `sudo -n env PYTHONPATH=src .venv/bin/python scripts/refresh-club-events.py`. Inspect the cached upcoming event dates. At fresh idle, run `sudo -n bash scripts/activate-night-riders-photobooth.sh --restart`. Restore the updater timer and verify the active service, menu/idle selector, video load, live generation and 23:00/07:00 simulations. Do not interrupt guests.

Rollback: while freshly idle, revert the release commit on the runtime branch, restore its private pre-release `.env` backup, and restart using `restart-artifact-if-idle.sh`. Keep unrelated runtime changes and untracked files. A generated bitmap and full video decode do not prove the physical printed receipt. If USB printing is disconnected, report it separately.
